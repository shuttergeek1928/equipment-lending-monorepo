# Equipment Lending Monorepo

This repo contains a monorepo skeleton for the Equipment Lending assignment:
- React frontend
- Java services: authentication & equipment management
- .NET services: borrowing & returns, dashboard
- PostgreSQL for data

## Quick start (dev)
1. Copy `.env.example` -> `.env` and adjust if needed.
2. Run `./scripts/start-all.sh`
3. Open services:
   - Frontend: http://localhost:3000
   - Java Auth: http://localhost:8081
   - Java Equipment: http://localhost:8082
   - .NET Borrow: http://localhost:8083
   - .NET Dashboard: http://localhost:8084

## Backend Services

This document describes the complete backend architecture for the School Equipment Lending Portal. The system is built as a Java/Spring Boot microservice application, composed of two distinct services that work together.

auth-service: A dedicated Identity Provider that manages user accounts and issues JWT tokens.

equipment-service: A protected Resource Server that manages the equipment inventory and validates JWT tokens.

System Architecture

The services communicate via REST APIs. The frontend client is responsible for orchestrating the flow:

The client authenticates against the auth-service to receive a JWT.

The client then includes this JWT as a Bearer Token in Authorization headers when making protected calls (like POST, PUT, DELETE) to the equipment-service.

The equipment-service validates the token's signature (using a shared secret) and checks the user's roles (e.g., ROLE_ADMIN) before granting access.

1. Auth Service

Service Port: http://localhost:8081

This service's sole responsibility is to manage user identity: user registration (signup), user authentication (login), and the generation of JSON Web Tokens (JWT).

Tech Stack

Java 17 / Spring Boot 3.x

Spring Security 6.x: For password encoding and authentication.

Spring Data JPA / Hibernate: For database interaction.

PostgreSQL: Database for users and roles tables.

JJWT (Java JWT): For creating and signing JWTs.

Setup & Running

Create Database: CREATE DATABASE auth_db;

Configure: Update src/main/resources/application.properties with your PostgreSQL username and password.

Database Init:

spring.jpa.hibernate.ddl-auto=update automatically creates tables.

spring.sql.init.mode=always runs src/main/resources/data.sql to populate the roles table (e.g., ROLE_STUDENT, ROLE_ADMIN).

Run: mvn spring-boot:run

Security

The JWT token generated by this service includes userId (UUID), roles (Array), and sub (username) as claims.

The endpoints /api/auth/** (login/signup) are public.

API Endpoints (/api/auth)

POST /signup: Registers a new user (requires username, email, password, role array).

POST /login: Authenticates a user (requires username, password) and returns a JwtResponse (id, username, roles, token).

2. Equipment Service

Service Port: http://localhost:8082

This service manages the equipment inventory. It is a Resource Server, meaning it does not issue tokens, but it validates them to protect its endpoints.

Tech Stack

Java 17 / Spring Boot 3.x

Spring Security 6.x: For endpoint protection (@PreAuthorize).

Spring Data JPA / Hibernate: For database interaction.

PostgreSQL: Database for the equipments table.

JJWT (Java JWT): For parsing and validating incoming JWTs.

Setup & Running

Create Database: CREATE DATABASE equipment_db;

Configure: Update src/main/resources/application.properties with your PostgreSQL credentials and the critical jwtSecret.

# --- CRITICAL ---
# This secret MUST be identical to the one in the 'auth-service'
school.app.jwtSecret=SuperSecretKeyForSchoolLendingJWTs


Database Init:

spring.jpa.hibernate.ddl-auto=update automatically creates the equipments table.

Run: mvn spring-boot:run

Security

GET requests (/api/equipment and /api/equipment/{id}) are public.

POST, PUT, and DELETE requests are Admin Only.

They require a valid JWT token.

The user's token must contain the ROLE_ADMIN claim.

This is enforced by the @PreAuthorize("hasRole('ADMIN')") annotation on the controller methods.

API Endpoints (/api/equipment)

GET /: (Public) Gets a list of all equipment.

GET /{id}: (Public) Gets a single equipment item by its UUID.

POST /: (Admin Only) Adds a new item using an EquipmentCreateDTO.

PUT /{id}: (Admin Only) Updates an existing item using an EquipmentUpdateDTO.
